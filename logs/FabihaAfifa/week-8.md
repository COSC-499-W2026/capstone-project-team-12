## Challenges and lessons learned

One of the main challenges this week was implementing idempotent scoring across multiple layers of the backend. A location result may be processed more than once, so simply incrementing a student's points or game total could produce incorrect results. I addressed this by using the points ledger to prevent duplicate awards and calculating game-session totals from persisted location scores.

Another challenge was maintaining database consistency while introducing several related models and migrations. The points ledger, language statistics, achievement definitions, and user achievement records all required constraints and relationships. I learned to verify the migration dependency chain after other branches merged, rather than assuming the original Alembic revision order remained valid.

I also encountered test failures caused by assumptions that did not match the actual database constraints. Examples included inactive-enrolment timestamps, active game-session restrictions, and invalid enum values. Correcting these issues reinforced the importance of using the existing database models and application definitions as the source of truth when writing tests.

Finally, implementing the student engagement and achievements endpoints highlighted the value of separating read-only data retrieval from scoring and achievement updates. Centralizing level calculations and reusing the existing engagement interface reduced duplicated logic and helped maintain consistent behavior across services.
